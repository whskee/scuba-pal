To organize database, architecture, deployment, and client-specific platforms in a large Docusaurus site, use a modular directory structure under the root docs/ folder. Group shared backend concepts separately from client-facing code.
Here is the industry-standard directory structure optimized for deep nested navigation and sidebar generation:
## Recommended Directory Structure

my-docusaurus-site/
├── docs/
│   ├── 01-intro.md               # Quickstart and unified application overview
│   │
│   ├── architecture/             # Global system architecture
│   │   ├── system-overview.md
│   │   ├── authentication.md     # Shared auth flows (OAuth/JWT)
│   │   └── data-flow.md          # State management and event tracking
│   │
│   ├── database/                 # Database architecture and schemas
│   │   ├── schema-design.md      # Main relational or NoSQL diagrams
│   │   ├── migrations.md         # How to run and write migrations
│   │   └── caching.md            # Redis/Memcached architecture
│   │
│   ├── deployment/               # DevOps and CI/CD pipelines
│   │   ├── environments.md       # Dev, Staging, Production variables
│   │   ├── ci-cd-pipelines.md    # GitHub Actions / GitLab CI setups
│   │   └── cloud-infra.md        # AWS/GCP/Azure infrastructure layouts
│   │
│   ├── clients/                  # Client-specific applications
│   │   ├── mobile/
│   │   │   ├── ios/              # iOS setup, building, provisioning profiles
│   │   │   └── android/          # Android Gradle setups, keystores
│   │   ├── web/                  # Next.js/React/PWA frontend specifics
│   │   └── desktop/              # Electron/Tauri specifics (if applicable)
│   │
│   └── api/                      # Backend APIs used by clients
│       ├── rest-api.md
│       └── graphql.md

## Pro-Tips for Directory Management

* Auto-Generate Sidebars: Do not manually list every file. Use the category link option type: 'autogenerated', dirName: '.' in your sidebars.js file. It automatically reads your directory structure.
* Control Order with Prefixes: Docusaurus sorts files alphabetically. Prefix folder names or files with numbers (e.g., 01-architecture, 02-database) to force a specific order in the UI without changing the visible title.
* Use _category_.json: Drop a _category_.json file into each folder (like docs/clients/mobile/_category_.json) to define custom folder labels, collapsable states, or icons in the sidebar.
* Avoid Flat Files: Never mix mobile and database files in the root docs/ folder. Keeping the root folder limited to 5–6 core directories makes long-term maintenance seamless.

Based on that directory structure, here is exactly what your docusaurus.config.js navbar should look like to group everything cleanly without cluttering the screen.
## The Complete Navbar Code
Replace your themeConfig.navbar.items array with this configuration:

themeConfig: {
  navbar: {
    title: 'DevDocs',
    logo: {
      alt: 'Logo',
      src: 'img/logo.svg',
    },
    items: [
      {
        type: 'doc',
        docId: 'intro',
        position: 'left',
        label: 'Get Started',
      },
      {
        type: 'dropdown',
        label: 'Clients',
        position: 'left',
        // Highlights this dropdown when viewing any client doc
        activeBaseRegex: '^/docs/clients/', 
        items: [
          {
            to: 'docs/clients/web/overview',
            label: 'Web / PWA',
          },
          {
            to: 'docs/clients/mobile/ios/overview',
            label: 'iOS App',
          },
          {
            to: 'docs/clients/mobile/android/overview',
            label: 'Android App',
          },
        ],
      },
      {
        type: 'dropdown',
        label: 'Backend & Infra',
        position: 'left',
        activeBaseRegex: '^/docs/(architecture|database|deployment)/',
        items: [
          {
            to: 'docs/architecture/system-overview',
            label: 'Architecture',
          },
          {
            to: 'docs/database/schema-design',
            label: 'Database Design',
          },
          {
            to: 'docs/deployment/environments',
            label: 'Deployment & CI/CD',
          },
        ],
      },
      {
        type: 'doc',
        docId: 'api/rest-api',
        position: 'left',
        label: 'API Reference',
      },
      {
        href: 'https://github.com',
        label: 'GitHub',
        position: 'right',
      },
    ],
  },
}

## Why This Breakdown Works

* Clients Dropdown: Isolates frontend specifics so web and mobile engineers can jump straight to their respective environment setups.
* Backend & Infra Dropdown: Bundles architecture, database, and devops together. These topics are highly interdependent, so putting them in one dropdown keeps your top navbar clean.
* Active Base Regex: The activeBaseRegex property ensures that if a user is deep inside a database page, the Backend & Infra navbar item stays visually highlighted.
