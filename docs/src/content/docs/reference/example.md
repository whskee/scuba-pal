Reference pages are ideal for outlining how things work in terse and clear terms.
Less concerned with telling a story or addressing a specific use case, they should give a comprehensive outline of what you're documenting.

# Things I learnt
1. Adopt [Diátaxis](https://diataxis.fr) approach for technical documentation.
2. DRY (Don't Repeat Yourself) and YAGNI (You Ain't Gonna Need It)
3. Don't hardcode container names (bad practice) in Docker.
4. Make use of [environment variables](https://medium.com/@shivamg727583/stop-hardcoding-your-secrets-a-2-minute-guide-to-env-files-18fb4a0717f2)
